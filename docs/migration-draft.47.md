# Migration — 0.1.0-draft.47

Draft.47 adds the bilingual semi-automated rule TS03-A01 to TS03 and changes the control input declaration to include configuration. It qualifies only a bound, synthetic .invalid HTTP matrix with existing, removed and nonexistent route labels and supplied literal content markers. The native reader adds no DNS or network collection. A complete contradiction is fail; an incomplete or ambiguous case is inconclusive. The rule does not classify Google soft 404s.

Draft.47 adds conformance/ts03_response.py, interpreter version 46, capture adapter version 45, thirteen fingerprinted synthetic cases, the bilingual method/limits document, a dated source capture, and current generated control pages and examples. The report schema and current corpus are bound to draft.47. Old TS03 reports without TS03-A01 remain historical and are not upgraded or re-evaluated automatically. The new rule does not alter TS01–TS44 identifiers or reinterpret previous results. Existing atomic rule text for other controls is carried forward unchanged; its current edition reference is draft.47, while retained reports remain bound to their original version.

Migration guidance: preserve old reports exactly; use their original protocol and tool identities. To assess the new candidate, prepare a new report with the required configuration/http/content/intent records and include all three declared route states. Never convert absent evidence into a pass or NA. Whole-control NA still requires a separate positive inventory. No actual domain, persistent availability, Google visit, soft-404 classification, indexing or ranking is established.
